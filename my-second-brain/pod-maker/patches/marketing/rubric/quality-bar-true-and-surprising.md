# Candidate: a piece needs to be both true and surprising

**The candidate rule:** a strong piece is both TRUE (accurate, earned, not hype) and SURPRISING (says something the reader did not already assume). Only-true is a correct platitude that no one saves. Only-surprising is a stunt that gets a glance and no trust. Both together is what a buyer keeps. Test this *before* writing, not after: if a single-note competitor could have written the same take, the topic is not surprising enough; kill it and pick another.

**Why it might hold:** platitudes do not move people who already agree; stunts do not build the trust a purchase needs. The overlap is where attention and credibility meet.

**Why it might not (for you):** some markets reward reliable, unsurprising reassurance (compliance, safety, "we are the boring dependable one"). Surprise can read as unserious there.

**How the loop tests it:** when pieces that pass the both-true-and-surprising test outperform pieces that are merely accurate or merely provocative (per the outcome signal), log confirmations. Watch for the market rewarding plain reassurance instead.

**Confirmations:** 0 (seed hypothesis). This is a good default quality bar, not yet proven to be *your* bar. Some businesses define quality differently; that is why this is a candidate, not doctrine.

> The mechanism "there is a pre-write quality gate" is fixed doctrine (`doctrine.md`). *What* the gate checks (this true-and-surprising bar) is a tunable default, so it lives here as a candidate.
